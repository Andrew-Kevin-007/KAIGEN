# KAIGEN v3 landscape (design draft)

Status: comparison as of 2026-11-02, with peer rows and prior-art rows updated 2026-11-04 from docs/v3/PRIOR-ART-CHECK.md. Limited to the sources listed. Every cell carries a source URL or is marked unverified. Absence from a few searches is not proof of absence. Many facts are vendor-authored or secondary. We make no latency or speed comparison against any vendor. Nothing here claims mainnet, audits or measured results for KAIGEN.

Review limits. Searches ran through a US-only summarising search tool. Several repository READMEs were read through summarising fetches, not as code. The NEAR peer repos are hackathon drafts dated October 2026, testnet and unaudited. Every peer behaviour statement below is UNVERIFIED: README or source read only, no code run [PRIOR-ART-CHECK.md section 0].

## 3. KAIGEN versus the above

| Property | KAIGEN v2 (code read 2026-11-02) | KAIGEN v3 (proposed, not built) | Closest comparators |
| --- | --- | --- | --- |
| Enforcement location | Contract on the user's own account | Same | Eight of nine NEAR peers enforce on-chain per README or source (section 2; UNVERIFIED). Leash puts its vault on the contract's own account, as Mamori does (header comment, UNVERIFIED) [PRIOR-ART-CHECK.md C1]. OutLayer (TEE plus gateway); Safe, Argent, MetaMask (on-chain on other chains). On-chain enforcement is table stakes. |
| Rolling cap | Per token, account-wide, 24 h | Same, written invariant, property tests | Leash (rolling 24 h per README; a source read suggests a fixed window, UNVERIFIED); OpenZeppelin Stellar (per-rule period limits). Account-level aggregate: Leash and near-agent-spend-guard key totals per agent (UNVERIFIED); tridon's scope not stated; not determined for the others [PRIOR-ART-CHECK.md C4a]. |
| Allowlist | Off by default | Off by default, behaviour specified | Leash, near-agent-spend-guard, semilla1-guard-near, Veto, agent-allowance-guard (section 2; UNVERIFIED) |
| Queue with cancel | Yes, 24 h production floor | Plus expiry, `cancel_all`, per-key slots | Leash (README); Zodiac Delay, Phoenix (unverified this workflow) |
| Auto response to repeated misuse | Burn after N refusals in 24 h, no external actor | Same, with fixed counting rules | No NEAR repo found in the checked sources deletes a key after a count of refusals (see NOVELTY-CLAIMS.md C2) [PRIOR-ART-CHECK.md C2a]. Concept-level prior art: Openfort recommends revoking after N blocked attempts (2026-04-03); PolicyLayer `violation_burst` auto-pause sample (2026-01-05, shipped status UNDETERMINED) [PRIOR-ART-CHECK.md C2c]. Counting only: agent-allowance-guard `rejection_count` [PRIOR-ART-CHECK.md C2b]. External-detector pauses exist (Hypernative). |
| Events | NEP-297-style under standard `kaigen` | Extended | Leash (README), parity |
| Posture check | Views only | `attest()` plus cage-check from RPC | Key-listing tools exist (section 2). Three NEAR peers check part of an agent key's scope per README (privatepay-agent, near-agent-spend-guard, agent-allowance-guard); Veto checks on-chain policy values (UNVERIFIED). The combined check was not found in the checked sources [PRIOR-ART-CHECK.md C3a, C3b]. |
| Instant owner freeze | No | Not planned (sentinel is a stretch item) | OutLayer has one. Six of the nine NEAR peers expose an owner pause or freeze (UNVERIFIED) [PRIOR-ART-CHECK.md C1]. |
| Post-quantum | ML-DSA-65 admin, testnet protocol 88 only | Same. No early warning. | NEAR native rotation. KAIGEN adds nothing to rotation itself. |
| Deployment | Per-account contract | Hash-pinned global contract, if mainnet supports it | NEAR docs |
| Measured results | None for v3. v2 has testnet drill records in fire-tests/. | Week-3 numbers, including the same attack scripts against Leash and near-agent-spend-guard | None published by us yet |
